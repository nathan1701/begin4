A live Ghidra MCP connection (tools named mcp__ghidra__*) was used throughout. Confirm it's live at

it's connected and working, not broken).

This session's biggest lesson: **a heuristic file-offset table built by searching for known numbers
can be systematically wrong by a constant amount and still "confirm" several fields by coincidence**
(see ENERGY_SYSTEM_MAP.md §3.9 and §8's new bullet). When a code-confirmed offset (from disassembly,
applied to the actual runtime pointer) disagrees with a heuristic/file-offset-based one, trust the
code-confirmed one, and if static analysis can't settle which is real, a live memory read can - see
§3.9 for exactly how this session did that with the developer's own running copy of the game under
Wine (no Cheat Engine needed - plain Python + /proc/<pid>/mem + sudo, since the default
ptrace_scope=1 blocks same-user memory reads without it).
