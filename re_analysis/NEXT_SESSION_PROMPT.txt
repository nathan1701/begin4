CRITICAL CONTEXT - WHAT PATH B4 ESTABLISHED
==================================================================================

There is NO single "4:1 WES:RES ratio" constant. Two separate, real energy-balance rules
both happen to reuse the same 4.0 literal (0x00464ad8):

1. DRIVE charges and drains at reactor_rate x 4.0 (FUN_00409740, ship+0x708 array,
   0x38-byte records)
2. SHIELD reinforcement costs 4x the power of a regular shield (FUN_0040b320, ship+0x7f8
   array, 0x48-byte records) - this is the literal "Reinforced shields require 4x power"
   mechanism from the manual/game text

CLOAK (FUN_0040a690, ship+0xc20) uses neither pattern - flat crew-count-based cost, no 4.0.

WEAPONS (Phaser Banks / Torpedo Tubes / Probe Launchers) have not been traced at all.
This is the single biggest gap - the manual's "WES" (Weapon Energy Storage) side of the
ratio has never actually been examined in code. Priority 1 below.

The generic constant 0x00464688 = 100.0 is NOT energy-related. It's a percent-to-fraction
helper used in 35+ unrelated functions across the whole codebase. Don't chase it further -
it's a solved, closed question (see ENERGY_SYSTEM_MAP.md section 4).

GHIDRA CONNECTION
==================================================================================

A live Ghidra MCP connection (tools named mcp__ghidra__*) is available and was the key tool
in Path B4 - direct decompile/disassemble/xref queries, not manual byte-searching. Confirm
it's connected at the start of the session (e.g. mcp__ghidra__get_current_function or a
get_xrefs_to call on a known address). If it's not available, the Python tools
(binary_tools.py, energy_system_analysis.py) still work for static analysis but xref-based
tracing (which is how most of Path B4's findings were made) won't be possible.

Useful Ghidra tools from this session: decompile_function_by_address, disassemble_function,
get_xrefs_to, get_function_by_address, list_strings (with a `filter` argument - very useful
for finding a subsystem's format strings, e.g. filter="Phaser" or filter="Bank").
